# assessment-of-dehydration-frontend

SPA для гостя приложения «Оценка обезвоживания» (Vibes-подобная лента признаков обезвоживания, в терминах курса — `услуг`). Стек: React + TypeScript, сборщик Vite, React Router и компоненты React-Bootstrap. Интерфейс свёрстан под вертикальный экран телефона и повторяет HTML-шаблоны из лабораторной №1 (ветка `database` репозитория бэкенда).

## Запуск

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # production-сборка в dist/
npm run lint     # oxlint
npm run format   # форматирование prettier
```

## Страницы

Приложение — «телефон» шириной 360px. Снизу на каждой странице расположена навигационная панель.

### Нижняя навигационная панель

Четыре кнопки-иконки слева направо:

| Кнопка     | Иконка            | Действие                           | Доступна гостю        |
| ---------- | ----------------- | ---------------------------------- | --------------------- |
| Лента      | домик             | переход на `/feed` (первая услуга) | да                    |
| Добавление | плюс              | —                                  | нет, кнопка неактивна |
| Плитка     | сетка 2×2         | переход на `/signs`                | да                    |
| Вход       | дверь со стрелкой | —                                  | нет, кнопка неактивна |

Активная страница выделена голубой рамкой. Недоступные кнопки серые, при наведении курсор `not-allowed`.

### Лента — `/feed`, `/feed/:id`

Одна услуга на весь экран:

- **видео** услуги на фоне (автовоспроизведение без звука, по кругу), обложка — изображение услуги;
- **плашка с информацией**: название и описание услуги;
- **💧** — коэффициент обезвоживания;
- **🔺** — максимальный коэффициент обезвоживания;
- **кнопка «сердце»** (лайк) — неактивна: гость не может ставить лайки;
- **кнопка-стрелка «Следующая запись»** — переход к следующей опубликованной услуге. После последней лента начинается с первой.

`/feed` открывает первую услугу, `/feed/:id` — услугу с этим `id` (или ближайшую следующую). Если услуг нет, выводится «Лента пуста».

### Плитка — `/signs`

Фильтр (закреплён сверху при прокрутке):

- **поле «Поиск по названию»** — подстрока названия без учёта регистра;
- **слайдер с двумя ползунками** — диапазон коэффициента обезвоживания «от» и «до» (значения над ползунками). Верхняя граница слайдера — максимальный коэффициент среди услуг, найденных по названию;
- **кнопка-стрелка «Применить фильтр»** — применяет поиск и диапазон. Применённые значения сохраняются в адресе: `/signs?search=су&min=3&max=9`.

Ниже идёт сетка карточек в две колонки. Каждая карточка содержит:

- изображение услуги;
- значок **💧** с коэффициентом обезвоживания;
- значок **♥** с количеством лайков;
- название услуги.

Нажатие на карточку открывает эту услугу в ленте (`/feed/:id`). Если ничего не найдено, выводится «Ничего не найдено».

## Изображение и видео по умолчанию

Медиафайлы услуг хранятся в MinIO: `http://localhost:9000/dehydration/`. Если поле `imgSrc` / `vidSrc` в услуге пустое или файл не удалось загрузить, подставляются файлы из самого проекта:

- `public/DefaultImage.svg` — изображение по умолчанию (карточки плитки, обложка видео в ленте);
- `public/DefaultVideo.mp4` — видео по умолчанию в ленте.

Подстановку выполняют компоненты `SignImage` и `SignVideo` (`src/components/SignMedia/SignMedia.tsx`).

## Используемые хуки

| Хук               | Где                                               | Назначение                                                                |
| ----------------- | ------------------------------------------------- | ------------------------------------------------------------------------- |
| `useState`        | `FeedPage`, `SignsPage`, `SignImage`, `SignVideo` | загруженные данные, значения полей фильтра, признак ошибки загрузки медиа |
| `useEffect`       | `FeedPage`                                        | загрузка услуги при изменении `:id`                                       |
| `useEffect`       | `SignsPage`                                       | расчёт границы слайдера и загрузка карточек при изменении фильтров        |
| `useParams`       | `FeedPage`                                        | `id` услуги из адреса                                                     |
| `useNavigate`     | `FeedPage`                                        | переход к следующей услуге                                                |
| `useSearchParams` | `SignsPage`                                       | применённые фильтры в адресной строке                                     |

Redux и React Context не используются: состояние хранится в компонентах страниц, в дочерние компоненты оно передаётся через props.
